## Overview

Statements not available in ABAP Cloud.

> **ATC Finding Message:** `Statement is not available in ABAP Cloud; use a released API`

## Rationale

ABAP Cloud restricts the language to a released subset, so statements such as SUBMIT, CALL TRANSACTION, EXEC SQL, or CREATE OBJECT for OLE automation parse as unknown syntax and can never be transported to a Steampunk system. The check derives its catalog directly from abaplint's ABAP Cloud statement artifacts, which mark 165 statements as unavailable, and reports PREF_CLOUD on every statement whose leading keyword sequence matches a forbidden pattern. Allowed statements that share a prefix (CALL FUNCTION, EXPORT ... MEMORY ID, CREATE OBJECT ... TYPE) are protected by longest-prefix disambiguation, so legacy detection does not spill over into released syntax.

### Non-Compliant

```abap
SUBMIT zreport.

SORT BY field.

CALL TRANSACTION 'ZTRAN'.
```

### Compliant

```abap
cl_report_runner=>run( 'ZREPORT' ).

SORT itab_stable BY field.

cl_transaction_runner=>run( 'ZTRAN' ).
```

## Suppression

To suppress findings for this rule, append the pseudo-comment to the statement:

```abap
" Standard pseudo-comment:
... "#EC PREF_CLOUD_READY

" SAP CI_ prefix format:
... "#EC CI_PREF_CLOUD_READY
```

## Generated Statement Catalog

The forbidden and allowed keyword patterns live in `/SKYL/CL_CLOUD_STMTS`, which is generated by `scripts/generate-cloud-statements.mjs` from abaplint's `ArtifactsABAP`. Regenerate it with `npm run build`; `npm test` verifies that the committed catalog is up to date. The catalog contains 165 statements that abaplint marks with a root `LangVersNot(Cloud)` matcher, collapsed into 205 keyword prefixes. Statements that are only restricted for `KeyUser` remain valid in ABAP Cloud and are not reported.

## Matching

- Only the leading token sequence is inspected; operands are never evaluated.
- Prefix matching uses `find_token_sequence( ... ) = 1`, so a forbidden keyword must appear at the start of the statement.
- Longest-prefix disambiguation keeps shared keywords usable: `CALL` is forbidden, but `CALL FUNCTION` and `CALL METHOD` are allowed; `CREATE OBJECT` is allowed unless it is an OLE automation call.
- Three constructs need structural special cases because forbidden and allowed variants share the same prefix: `AT PFnn`, dataset `SORT` without an internal table, and `CREATE OBJECT` with a non-class section.

## Notes

- The check is remote enabled because it only inspects the delivered statement stream and does not use RTTI.
- No QuickFix is offered; replacing a legacy statement requires a released API decision that cannot be automated safely.
- Suppress an intentional exception with `"#EC PREF_CLOUD_READY` on the affected statement.
